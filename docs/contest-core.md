## 0. Что это за конкурс ✅

Конкурс для **административно-управленческих команд СПО** (колледжей).

Состав команды — **4 человека**:
- 3 преподавателя (административно-управленческий состав)
- 1 студент

Конкурс делится на две последовательные части:

| Этап | Кто субъект | Суть |
|------|-------------|------|
| **«Я»** | отдельный участник | индивидуальная подготовка: видеокурс + задания в тренажёре |
| **«Мы»** | команда | командная работа (описывается ниже, раздел 2) |

Порядок жёсткий: сначала «Я», потом «Мы». Этап «Мы» недоступен, пока участник не закрыл «Я».

Терминология «Я» / «Мы» уже зашита в тренажёр — см. `src/lib/mayakProgressModel.js`:
- `YA_FORMAT_TYPES` — 6 форматов контента части «Я» (Текст, Аудио, Изображение, Интерактив, Видео, Данные)
- `WE_DIRECTIONS` — 6 направлений части «Мы» (модель «ЗВЕЗДА»)

Это не совпадение, а точка стыковки: конкурс переиспользует ту же модель.

## 1. Этап «Я» 🟡

### 1.1 Состав этапа

После регистрации участник проходит **видеокурс из 8 уроков**:

| № | Урок | Тип задания |
|---|------|-------------|
| 1 | Вводный | знакомство с тренажёром / фреймворком |
| 2 | Текст | задание формата «Текст» |
| 3 | Аудио | задание формата «Аудио» |
| 4 | Изображение | задание формата «Изображение» |
| 5 | Интерактив | задание формата «Интерактив» |
| 6 | Видео | задание формата «Видео» |
| 7 | Данные | задание формата «Данные» |
| 8 | Заключительный | подведение итогов, переход к этапу «Мы» |

Уроки 2–7 один в один ложатся на `YA_FORMAT_TYPES` из тренажёра.

Контента пока нет — уроки заливаются постепенно по ходу конкурса.

### 1.2 Правило открытия уроков

**Последовательное: прошёл урок N → открылся урок N+1.** Без таймингов.

«Прошёл» = посмотрел видео **и** выполнил задание к уроку в тренажёре.

Вариант с открытием по расписанию отложен — вернуться, если понадобится синхронизировать поток участников по датам.

### 1.3 Связка «урок ↔ тренажёр»

Решение: **видео и задания не смешиваются в одном интерфейсе.**

Поток участника:

```
Блок уроков (портал)
  └─ Урок N: видео + описание задания
        └─ [Выполнить задание] ──► Тренажёр (конкурсная колода, задачи урока N)
                                        └─ задание выполнено ──► возврат в блок уроков
        ◄── урок N закрыт, открыт урок N+1
```

Почему так, а не встраивать видео в тренажёр:
- тренажёр — среда выполнения, у него своя логика сессий, оценки, ролей; видеоплеер туда не относится;
- уроки — линейный курс, тренажёр — набор колод; разная модель прогресса;
- возврат из тренажёра в курс проще, чем протаскивать курс через сессии тренажёра.

### 1.4 Архитектура: конкурс — потребитель тренажёра 🟡

Главное ограничение: **тренажёр в проде, им пользуются прямо сейчас.** Значит конкурс не имеет права менять его поведение для существующих сценариев (токены, сессии, столы, инспектор, админка).

Решение — слоями, без смешивания:

```
┌─ КОНКУРС ──────────────────────────────────┐
│  /contest — 8 уроков, прогресс, гейты      │  новый домен, свои файлы, свои данные
│  привязка к профилю портала (userId)       │
└───────────────┬────────────────────────────┘
                │  единственная точка касания:
                │  контекст доступа { tokenType, sectionId, taskRange }
┌───────────────▼────────────────────────────┐
│  ТРЕНАЖЁР — как есть                       │  не переписывается
│  legacy-токены · сессии · админка · Qwen   │
└────────────────────────────────────────────┘
```

Тренажёр про конкурс ничего не знает. Он знает только «пришёл валидный контекст доступа на такую-то колоду и такой-то диапазон задач» — этот контракт у него уже есть.

**Точка стыковки ровно одна:** `resolveMayakTokenContext()` в [mayakTokenContext.js](src/lib/mayakTokenContext.js) сейчас возвращает `{ tokenType: "legacy" | "session" | "bypass", sectionId, taskRange, ... }`. Добавляется четвёртая ветка `tokenType: "contest"`.

Что она делает:
- «токеном» выступает авторизация портала (`users_access_token`) + номер урока;
- ничего не хранится в `mayakTokens.json`, ничего не расходуется (`usedCount` не трогается);
- `sectionId` = конкурсная колода, `taskRange` = диапазон задач текущего урока;
- `sessionId` пустой → конкурсные прохождения не попадают в сессионный дашборд и не ломают статистику столов.

Существующие ветки не редактируются — только новая, ниже по цепочке. Откат = удалить ветку.

### 1.5 Конкурсная колода

Конкурс = **обычная колода контента** (`sectionId`, папка с `index.json` + запись в `manifest.json`, см. [mayakContentStorage.js](src/lib/mayakContentStorage.js)). Ничего нового в формате контента не появляется.

Что даёт бесплатно:
- редактор колод в админке работает как есть;
- расчёт прогресса по 6 форматам уже реализован (`classifyTask`, `resolveFormatKey`);
- оценка ответов и артефакты профиля работают как есть.

Разметка: 8 уроков = 8 диапазонов задач внутри одной колоды. Задачи уроков 2–7 размечаются `contentType` соответствующего формата (Текст / Аудио / Изображение / Интерактив / Видео / Данные), урок 1 — `Старт`.

### 1.6 Где живёт что

Уточнено после подключения бэкенда (`../back/RSK_back`, см. Приложение Б). `learning_service` — наш репозиторий, а не чёрный ящик, поэтому уроки конкурса живут там же, где обычные, а не дублируются локально.

| Данные | Где | Почему |
|--------|-----|--------|
| Уроки: название, номер, видео, описание | `learning_service`, таблица `courses` | модель уже есть, второй курсовый движок не нужен |
| Связь урока с колодой тренажёра | `learning_service`, **новые поля** `courses.trainer_section_id` / `trainer_task_range` | иначе урок не знает, какие задачи открывать |
| Разделение «обычные уроки» / «конкурс» | `learning_service`, **новое поле** `courses.track` | без него конкурсные уроки ломают гейт `learning` (см. ниже) |
| Прогресс по урокам | `learning_service`, `user_progress` | уже есть |
| Сдача задания и её статус | `learning_service`, `submissions` (`на рассмотрении` / `одобрен` / `отклонён`) | модерация уже есть |
| Выполнение задания | тренажёр, как обычно (`saveTaskAttempt`, `completions/finalize`) | не дублируем логику выполнения |
| Факт «задание сделано» → сдача | BFF `rsk_fr`: читает историю тренажёра по userId → шлёт `submissions/submit` | не доверяем клиенту, вернувшемуся с `?done=1` |

**Критично:** `LearningStatusCRUD.check_user_completed_all_courses` считает **все** строки таблицы `courses` без фильтра. Если просто добавить 8 конкурсных уроков, флаг `learning` погаснет у всех, кто уже прошёл обучение, — «Команды» и «Проекты» закроются у живых пользователей. Поэтому поле `track` обязательно, и обе проверки (список курсов и подсчёт завершённости) должны по нему фильтроваться.

`learning_service/app/crud/course_crud/learning_status_crud.py:12`

### 1.7 Поток участника

```
регистрация на портале
   └─ вкладка «Конкурс» → /contest
        └─ Урок 1: видео + описание задания
              └─ [Выполнить задание]
                    → /tools/mayak-oko?contest=1
                    → тренажёр: конкурсная колода, задачи урока 1
                    → задание выполнено (пишется в историю тренажёра по userId)
                    → возврат на /contest/lesson/1
        └─ сервер сверил историю тренажёра → урок 1 закрыт → открыт урок 2
   ...
   └─ урок 8 закрыт → участник допущен к этапу «Мы»
```

### 1.8 Что гарантирует «не поломать»

- ни один существующий файл тренажёра не переписывается — только добавляется ветка в резолвер контекста;
- вход по легаси-токену и по сессионному токену идёт прежними путями, байпасы не трогаются;
- конкурсные прохождения не создают сессий → сессионный дашборд, столы, инспектор не задеты;
- конкурс выключается флагом, не трогая тренажёр;
- откат конкурса = удаление конкурсного домена + одной ветки.

### 1.9 Как заливается контент этапа «Я» ✅

Три разных канала, у каждого своё хранилище. Это важно не перепутать.

| Что | Где лежит | Кто и как заливает |
|-----|-----------|--------------------|
| Видеоурок | `learning_service`, `courses.download_url` | ссылка на RuTube-embed, через админку обучения или напрямую |
| Название и описание урока | `learning_service`, `courses.lesson_name` / `description` | там же |
| Текст задания (цель, шаги, результат) | **пока код**: `src/lib/contestTrainerTasks.js` | временно; переезжает в `courses`, когда появятся поля |
| PDF задания, инструкция, карта | колода тренажёра: `<sectionId>/Files/<номер>.pdf`, `Instructions/`, `Maps/` | админка МАЯКа `/admin/mayak-content` |
| Ответы участников | `data/contest-answers/` | загружаются самими участниками |

**PDF задания класть можно и нужно** — механизм в тренажёре уже есть и используется в боевых колодах: например, в `901-1000` лежат 47 файлов вида `910.pdf`, в `8001-8100` — инструкция `8017.pdf`. Файл именуется номером задачи, привязка автоматическая.

В конкурсном режиме материалы доступны сразу: в обычном режиме доступ к ним открывается запущенным таймером сессии, а в конкурсе таймера нет.

### 1.10 Статус этапа «Я» ✅ собран

Что работает от начала до конца, проверено на локальном стенде:

1. регистрация → письмо → подтверждение → вход;
2. после входа участник попадает в «Конкурс» (раздел `/cours`);
3. восемь уроков сеткой 4×2, лесенка: доступен только следующий;
4. «К уроку» ведёт прямо в тренажёр на нужный урок, ключ не требуется;
5. в тренажёре: лесенка уроков в шапке, задание с попапом, видеоурок, поле ответа (текст или файл до 20 МБ);
6. «Завершить задание» сохраняет ответ и закрывает урок, открывается следующий;
7. после восьмого — возврат к списку, все карточки зелёные.

Сквозной прогон восьми уроков: 8 из 8 закрыто, 8 ответов сохранено.

### 1.11 Что осталось незакрытым в этапе «Я» ⬜

1. **Контента нет.** Видео — один и тот же промо-ролик на всех уроках, тексты заданий — рыба, конкурсной колоды не существует (карта указывает на `1-100`).
2. **Выполнение задания не проверяется.** «Завершить задание» верит участнику: сервер не сверяет, работал ли он в тренажёре.
3. **Флаг `is_learned`** переключается фоновой задачей раз в час — после восьмого урока «Команды» и «Проекты» откроются не сразу.
4. **Нет финального экрана** «этап «Я» пройден» и перехода к этапу «Мы».
5. **Лесенка скрыта** на экранах уже 1200px.
6. Тексты заданий и связь урок→колода живут во фронте, а не в БД.

### 1.12 Осталось решить ⬜

3. **Что делать с попытками** — можно ли перепройти задание урока, и что тогда с прогрессом?

### Флаг `is_learned` обновляется не сразу

Прохождение всех курсов **не** переключает флаг в профиле. `learning_service`
считает завершённость по запросу (`check_user_completed_all_courses`), а поле
`user_profile.is_learned` проставляет фоновая задача Celery:

- `learning_service/app/services/celery_app.py` — расписание: ежечасно и в 03:00;
- `learning_service/app/services/learning_tasks.py` — сама сверка и обновление;
- ручной запуск: `POST /learning/api/learned/test-learning/sync-update-user/{id}` (нужны права админа).

Следствие для конкурса: участник закрыл последний урок, а «Команды» и «Проекты»
откроются только после ближайшего пересчёта — до часа ожидания без объяснений.
Проверено на локальном стенде: 8 из 8 пройдено, `is_learned: false`.

### Чего не хватает для конкурса

1. `courses.track` — нет разделения на потоки, гейт считает все курсы разом.
2. `courses.trainer_section_id` + `courses.trainer_task_range` — урок не связан с колодой тренажёра.
3. Последовательное открытие уроков нигде не enforced — лесенка рисуется фронтом, бэк отдаёт все курсы.
4. `submissions.file_url` — `NOT NULL`, заточен под «вставь ссылку». Для конкурса туда ляжет ссылка на прохождение в тренажёре либо поле придётся ослабить.
5. Нет попыток/истории сдач по уроку — одна запись на пару (user, course).

Оценка изменений бэка: одна миграция alembic (3 колонки) + фильтр по `track` в двух местах. Всё остальное переиспользуется.
