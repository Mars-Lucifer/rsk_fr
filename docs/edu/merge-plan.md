# Слияние «Организаций» и «Колледжей» в один раздел

Состояние на 27.08.2026. Данные уже объединены: справочник залит в
`orgs_service`, дубля организаций между хранилищами нет — есть 4 163 записи,
опознаваемые по ИНН. Осталось свести экраны.

## Что сводим

| | `/organizations` | `/edu` |
|---|---|---|
| Список | поиск по названию, регион, сортировка по индексу / названию / участникам | поиск по названию, ИНН и городу, регион, вид, аккредитация, 4 сортировки |
| Карточка | индекс ЗВЕЗДА и 6 осей, участники, команды, ИНН, регион | лицензии, программы, адреса занятий, контакты, руководитель, реквизиты, рейтинг bus.gov.ru |
| Ключ карточки | числовой `id` из `orgs_service` | ИНН |
| Источник | PostgreSQL `orgs_service` | локальный `edu.sqlite` |

Ни один экран не является надмножеством другого: у одного метрики конкурса,
у другого сведения реестров.

## Три решения, которые определяют всё остальное

**1. Адрес раздела — `/organizations`.** Не `/edu`: на `/organizations` уже
ссылаются профиль (`src/components/pages/profile/index.js:270`) и команды
(`src/components/pages/teams/index.js:203`). Переезд на новый адрес означал бы
правку чужих экранов и битые ссылки в уже разосланных письмах.

**2. Ключ карточки — ИНН, а не `id`.** Числовой `id` — внутренний счётчик
`orgs_service`: он поменяется при любой перезаливке, и ссылка на организацию
протухнет. ИНН стабилен, узнаваем и совпадает с ключом реестра.

Старые ссылки по `id` не ломаем: маршрут принимает оба вида. 10 или 12 цифр —
это ИНН; всё остальное считается `id`, по нему находится ИНН и отдаётся
постоянный редирект.

**3. Хранилища остаются раздельными, но каждое владеет своим.** Справочник
владеет сведениями реестров, `orgs_service` — метриками конкурса. Соединение по
ИНН при отрисовке карточки. Переносить 98 тысяч программ и 14 тысяч адресов в
PostgreSQL сейчас не нужно: это отдельная работа, и слияние экранов её не ждёт.

## Шаги

### Шаг 1. Метрики участия в фасаде справочника

`src/lib/eduParticipation.js` — новый модуль: по списку ИНН возвращает индекс,
число участников и команд из `orgs_service` через `/api/org/*`.

Пустой ответ — не ошибка: организация может не участвовать в конкурсе, и это
норма, а не сбой. Недоступный бэкенд тоже не должен ронять страницу — справочник
обязан открываться без него.

*Проверка:* `node scripts/edu-participation-check.mjs` — по известному ИНН
возвращаются нули; при погашенном `orgs_service` функция отдаёт пустую карту,
а не бросает исключение.

### Шаг 2. Карточка организации

`src/pages/organizations/[organ].js` переписывается на карточку из `/edu/[inn]`
плюс блок участия сверху: индекс ЗВЕЗДА, шесть осей, участники, команды.

Блок участия показывается, **только когда организация в конкурсе**. Шесть нулей
на карточке колледжа, который о конкурсе не слышал, — это не информация, а шум.

*Проверка:* кадром — `/organizations/0263002030` открывает карточку с лицензиями
и программами; `/organizations/4` (старый числовой id) отдаёт редирект на неё же
по ИНН; несуществующий ИНН — 404, а не 500.

### Шаг 3. Список

`src/pages/organizations/index.js` заменяется списком из `/edu` с добавлением:

- переключатель «Все / Участники конкурса»;
- сортировка «по индексу» — доступна только вместе с фильтром участников,
  иначе она сортирует 4 163 нуля и порядок выдачи становится случайным.

*Проверка:* «Участники конкурса» сейчас даёт пустой список с внятным текстом
«В конкурсе пока никто не участвует» — это верное состояние до запуска, а не
поломка. Остальные фильтры дают те же числа, что и на `/edu`: 4 163 всего,
206 по Москве, 17 без действующей аккредитации.

### Шаг 4. Переезд `/edu`

`/edu` и `/edu/[inn]` становятся редиректами на `/organizations`. Страницы не
удаляются сразу: адреса уже могли разойтись по переписке.

`src/pages/api/edu/orgs/*` остаются как есть — это контракт данных, он не
меняется от слияния экранов.

*Проверка:* `/edu` отдаёт 308 на `/organizations`, `/edu/0263002030` — на
`/organizations/0263002030`.

### Шаг 5. Меню

В `src/components/layout/Aside/Nav.js` остаётся один пункт «Организации».
Пункт «Колледжи» убирается.

*Проверка:* кадром — в меню один пункт, он ведёт на общий раздел.

### Шаг 6. Сборка и проверки

*Проверка:* `npm run build` — код 0; `node scripts/edu-registry-check.mjs` —
все проверки проходят.

## Что сознательно не делается

| Отложено | Почему |
|---|---|
| Перенос программ, лицензий и адресов в PostgreSQL | 98 тыс. и 14 тыс. строк; слияние экранов от этого не зависит |
| Отказ от локального `edu.sqlite` | пока справочные сведения живут в нём, он нужен |
| Страница участников организации (`members.js`) | запрос к API в ней закомментирован, живых данных нет |
| Сортировка по числу участников | участников ноль до запуска конкурса |

## Порядок и риски

Шаги 1–3 можно делать подряд, 4 и 5 — только после того, как объединённый
раздел проверен кадром: до этого момента `/edu` остаётся рабочим запасным
входом.

Главный риск — ссылки из профиля и команд. Они ведут по числовому `id`, и если
редирект из шага 2 не заработает, пользователь получит 404 там, где раньше была
рабочая ссылка. Поэтому проверка редиректа стоит в том же шаге, а не в конце.
