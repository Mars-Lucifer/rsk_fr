# Справочник образовательных организаций

Колледжи и техникумы России — 4 182 организации по всем 89 субъектам. Источник:
выгрузка четырёх государственных реестров от 25 августа 2026 года
(`БАЗА_ОБРАЗОВАТЕЛЬНЫХ_ОРГАНИЗАЦИЙ_РОССИИ`, файл `4_Полная_база/baza.sqlite3`).

Портал работает не с исходной выгрузкой на 536 МБ, а со сборкой на 42 МБ,
где осталось только среднее профессиональное образование и только нужные колонки.

## Где лежит файл

Путь задаётся `EDU_DB_PATH`, по умолчанию — `.tools/edu/edu.sqlite`.

Каталог `.tools/` выбран не случайно: он уже в `.gitignore`, и главное — он
**вне `data/`**. В рабочих копиях `data/` — junction на общий рантайм главной
копии, файл там физически один на все шесть веток. Отслеживаемый git только в
одной из них, он ломает `git merge` во всех остальных: там он числится
неотслеживаемым, и git отказывается его перезаписать — даже когда содержимое
совпадает байт в байт.

Следствие: на прод справочник едет **копированием файла**, а не через `git pull`.

## Сборка

```bash
node scripts/edu-registry-build.mjs <путь к baza.sqlite3> [<куда положить>]
```

Скрипт падает, если не сходятся контрольные числа: пустой справочник, регион,
не сопоставленный с `public/data/regions.txt`, или потерянные ведущие нули в ИНН.
Тихо собранный наполовину справочник выглядит рабочим до первого запроса по
региону, которого в нём не оказалось.

## Проверка

```bash
node scripts/edu-registry-check.mjs [<путь к baza.sqlite3>]
```

Четырнадцать проверок. Без аргумента сверяется только справочник и фасад; с путём
к исходной выгрузке добавляется сверка с реестром — единственная, которая видит
дальше собственного результата сборщика.

## Правило отбора

В справочник попадает организация, которой лицензия разрешает вести программы
среднего профессионального образования:

```sql
SELECT DISTINCT l.inn
FROM licenses l
JOIN programs p ON p.license_id = l.license_id
WHERE p.level = 'Среднее профессиональное образование';
```

Это 4 182 организации — ровно столько колледжей и техникумов заявляет и сама
инструкция к архиву. Из них 499 — вузы с отделением СПО (`kind = 'both'`):
формально это вузы, но СПО они ведут, и абитуриенту колледжа они нужны.

Программы у отобранных организаций сохраняются **все профильные**, включая
высшее образование. Карточка описывает организацию целиком: умолчать, что у
колледжа при вузе есть ещё и бакалавриат, значит её исказить.

Соседние объёмы, если понадобятся, — правка одной строки в
`scripts/edu-registry-build.mjs`:

| Что нужно | Условие отбора | Организаций |
|---|---|---|
| колледжи и техникумы (сейчас) | `level = 'Среднее профессиональное образование'` | 4 182 |
| плюс чистые вузы | `… OR level LIKE 'Высшее образование%'` | 5 180 |
| всё профобразование | `section = 'Профессиональное образование'` | 5 259 |

Последняя строка добавляет автошколы и заводские курсы рабочих профессий —
это не колледжи.

Отбор по ОКВЭД (`85.21`) не годится: он теряет сотни профильных организаций,
у которых основной вид деятельности записан иначе — НИИ, семинарии, больницы.

## Что важно знать при доработке

**ИНН — строка, не число.** У 298 организаций из 4 182 ведущий ноль значим
(`0263002030`). Одно `Number(inn)` в любом звене цепочки — и организация молча
перестаёт находиться. По той же причине у организаций в справочнике **нет
собственных числовых id**: раз их не существует, их нечего по ошибке записать в
`Organization_id` профиля, а диапазоны id с таблицей `organizations` в
`orgs_service` пересекаются, и внешнего ключа там нет.

**Лицензия и аккредитация — разные вещи.** Лицензия даёт право учить, аккредитация —
право выдавать диплом государственного образца. Организация может иметь лицензию
без аккредитации. Два отдельных признака, не сливать в один «работает».

**`active_certs` — три состояния, не два.** `NULL` — организации нет в реестре
аккредитации (167 штук), `0` — свидетельства были и истекли (18), `N > 0` — есть
действующие. Три разных сообщения на карточке.

**Лицензия действует, а юрлицо — нет.** Реестр Рособрнадзора о состоянии в ЕГРЮЛ
не знает. Ликвидированные и ликвидируемые фасад из выдачи скрывает; реорганизуемые остаются — они продолжают учить.

**Юридический адрес — не место занятий.** Адрес регистрации в `edu_orgs.address`,
адреса занятий — в `edu_places`, их бывает до 83 у одной организации.

**Рейтинг — шкала 0..100**, а не пятибалльная: это независимая оценка качества
условий с bus.gov.ru, «не рассчитан» приходит как `-1.0` и превращается в `NULL`.

## Обновление данных

Реестры живые. Исходная выгрузка пересобирается инструментом `rlic` из того же
архива (`5_Инструмент_обновления`): полный прогон по стране — около двенадцати
часов, обновление контактов — минуты. Разумная частота — раз в квартал. После
пересборки выгрузки заново прогнать сборщик и проверку, обновить `SOURCE_DATE`
в `scripts/edu-registry-build.mjs` и скопировать файл на прод.

## Второй этап: перенос в orgs_service

`scripts/edu-registry.sql` написан так, чтобы исполниться дословно и в SQLite, и в
PostgreSQL: только общие типы, никаких `INTEGER PRIMARY KEY` как алиаса rowid,
`WITHOUT ROWID`, FTS5, `COLLATE NOCASE` и `ON CONFLICT`. Ключи таблиц программ и
адресов — хеши, а не сами поля: составной ключ здесь доходит до 8 557 байт при
пределе индексного кортежа btree в 2 704 байта, и перенос сломался бы именно на
той таблице, ради которой схема писалась общей.

Блокер переноса — не схема, а `orgs_service`: `create_org` делает `int(inn)`,
и 298 организаций с ведущим нулём через него физически не создать. Правится одной
alembic-ревизией, до этого связывать справочник с профилем нельзя.
