## learning_service — движок уроков

| Сущность | Поля | Файл |
|----------|------|------|
| `Course` | `lesson_name`, `lesson_number`, `description`, `file_extension`, `download_url` | `db/models/course.py` |
| `UserProgress` | `user_id`, `course_id`, `is_completed` | `db/models/user_progress.py` |
| `Submission` | `user_id`, `course_id`, `file_url`, `status` | `db/models/submission.py` |

Полезные ручки: `PATCH /courses/{id}/progress` — закрывает урок **без
модерации**, доступна обычному участнику. Именно её использует конкурс.

### Чего не хватает для конкурса

1. `courses.track` — нет разделения потоков. **Критично:**
   `check_user_completed_all_courses` считает все строки таблицы без фильтра,
   поэтому добавление конкурсных уроков в общий список гасит флаг `learning`
   у тех, кто прошёл обучение раньше.
2. `courses.trainer_section_id` + `trainer_task_range` — урок не связан с
   колодой тренажёра, связь пока живёт во фронте.
3. `submissions.file_url` — `NOT NULL`, 500 символов, рассчитан на ссылку.
   Ни текста ответа, ни вложения туда не положить — поэтому ответы участников
   лежат в файлах.

Оценка изменений: одна миграция alembic (3 колонки) + фильтр в двух местах.

### Флаг `is_learned` обновляется не сразу ⚠️

Прохождение всех курсов **не** переключает флаг в профиле. Его проставляет
фоновая задача Celery: ежечасно и в 03:00
(`services/celery_app.py`, `services/learning_tasks.py`).

Ручной запуск: `POST /learning/api/learned/test-learning/sync-update-user/{id}`
(нужны права админа).

Проверено: 8 из 8 уроков пройдено — `is_learned: false`.

## Локальный стенд 🟢 работает

Поднимается из репозитория бэкенда:

```
docker compose -f docker-compose.override.yml -f docker-compose.local.yml up -d
```

| Адрес | Что |
|---|---|
| `localhost:1234` | портал (`npm run dev`) |
| `localhost:8080` | шлюз к бэкенду (замена Traefik) |
| `localhost:8025` | почта: письма никуда не уходят, видны здесь |

Файлы стенда (не в гите, локальные): корневой `.env`, `.env` в шести
сервисах, `docker-compose.local.yml`, `local-gateway.conf`.

Переключение фронта на стенд — две строки в `.env.local`:

```
RSK_API_BASE=http://localhost:8080
NEXT_PUBLIC_RSK_API_BASE=http://localhost:8080
```

Убрать их — вернётся прод. По умолчанию (переменных нет) адрес прод-овый,
поэтому на сервере поведение не меняется.

Тестовый участник: `uchastnik@rsk-local.ru` / `Testpass123`.

## Мины стенда (найдены при запуске)

1. **Пароль БД обязан быть числом.** В конфигах сервисов `DB_PASS: int` —
   буквенный пароль роняет pydantic на старте.
2. **Healthcheck захардкожен на пользователя `postgres`** — с другим именем
   базы не проходят проверку и сервисы не стартуют.
3. **Сессионная кука** выдаётся с `Domain=.rosdk.ru; Secure` — на
   `http://localhost` браузер её молча выбрасывает. Решено адаптером в
   [portalApiBase.js](../../src/lib/portalApiBase.js), который срабатывает
   только при локальной базе.
4. **`orgs_service` и `teams_service` не прогоняют миграции** — в их
   докерфайлах нет `alembic upgrade head`, в отличие от остальных. Таблиц на
   чистой базе не создаётся вовсе.
5. **Миграции `orgs_service` не проходят** на чистой базе: тип `org_type_enum`
   создаётся дважды внутри одной миграции. Обход — создать таблицы из моделей.
6. **`teams_service` имеет `root_path="/teams"`**, из-за чего внутренний путь
   получается двойным: `/teams/teams/...`. `orgs_service` ходит в него по
   адресу, который работает только через прод-прокси.
7. **`teams-count` отвечает 404**, когда команд нет вообще, и роняет весь
   список организаций (502).
