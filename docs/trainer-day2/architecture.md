# Второй день МАЯК ОКО: как устроено

Карта направления `trainer-day2`. Первый день не описывается — он в корневом
`CLAUDE.md`; здесь только то, чем второй день от него отличается.

## Одной фразой

Второй день — тот же тренажёр, но карточка открывается **номером тайла**,
который человек держит в руках, а день идёт **тремя тактами**, общими на весь
зал.

## Что включает режим

Слог секции контента. `sectionId === "day2"` → второй день, и больше ничего
включать не надо: токен ведёт на секцию, секция определяет день.

Отдельный флаг пришлось бы держать синхронно в токене, в сессии и в рантайме —
он бы разъехался. Проверка: `isDay2Section` в `src/lib/mayakDay2Mode.js`.

## Номер — координата, а не идентификатор

Тайл `13` печатается один раз и служит годами, поэтому сам по себе ключом быть
не может. Ключ задания — `sessionId` + номер.

| Что | Ключ | Пример |
|---|---|---|
| деталь | номер | `13` |
| узел | два номера по возрастанию | `13-14` |
| переходник | узел плюс суффикс | `13-14:adapter` |
| изделие | центр стола | `10`, `20`, `30` |

Из номера считается **всё остальное**: десяток задаёт стол, позиция задаёт луч
и партнёра по паре. Пары зашиты в физику картона — `11+12`, `13+14`, `15+16`,
одинаково на всех трёх столах, — и сборка сессии их не выбирает, а получает как
данность.

Ключи ложатся в существующий рантайм без изменения схемы: `participant.tasks` —
это map со строковыми ключами.

## Пять модулей

Все чистые, все с тестами (`node --test src/lib/mayakDay2*.test.mjs`).

| Модуль | Отвечает за |
|---|---|
| `mayakDay2Mode.js` | признак режима, поиск карточки по номеру, имена столов, показ служебного ключа переходника человеку |
| `mayakDay2Input.js` | **что** человек хочет открыть: разбор одного поля ввода |
| `mayakDay2Takt.js` | **можно ли** это сейчас: автомат `DETAIL → NODE → PRODUCT` |
| `mayakDay2Schedule.js` | расписание зала 90·70·45 и три отметки внутри такта |
| `mayakDay2Palette.js` | цвета лучей, импортом из общего источника |

`mayakDay2Mode` намеренно без зависимостей: его импортирует серверный рантайм, и
палитра туда тащить компонент гайда не должна. Отсюда отдельный
`mayakDay2Palette`.

## Что нигде не хранится

**Такт участника.** Выводится из принятых заданий тем же приёмом, что фазы
первого дня в `mayakProgressModel`. Флаг в базе разошёлся бы с табло ведущего, и
разбирались бы в зале.

**Партнёрство.** Считается из номера. Хранить его — значит завести второй
источник правды рядом с картоном.

**Цвет луча.** Импортируется из `fieldLayout.mjs` — общего источника с полем
«МЫ». ТЗ (В9) требует одни коды на тайлах, поле, портале и карточках, а
расхождение любой строки называет дефектом производства. Тест падает, если в
`fieldLayout` переименуют направление.

## Что хранится на сервере и почему

**Номер тайла участника** — `participant.cardNumber`. Пока он жил во вкладке,
участник назначал себе стол сам первым набором, проверка «чужой стол» сравнивала
его выбор с его же выбором, а перезагрузка стирала номер вместе с тактом.

**Такт зала** — `bucket.day2Takt`, читается с дефолтом, поэтому сессиям на диске
миграция не нужна. Время задаёт сервер: три команды иначе разойдутся к вечеру на
четверть часа. Клиент получает абсолютную метку конца и вычитает её из своих
часов — тем же хуком, что отсчитывает время на проверку у инспектора.

## Чем второй день отличается в рантайме

| | День 1 | День 2 |
|---|---|---|
| кто инспектор | назначенная роль, соседний стол | **партнёр по паре** |
| джокер | пропуск проверки | **не выдаётся** |
| оценка промпта | `sova-check` | **скрыта, не заблокирована** |
| вводные карточки | три первые в сотне | **нет вовсе** |
| навигация | стрелки по колоде | **одно поле ввода** |
| право сдать | любое задание секции | **свои четыре ключа** |

Ограничение по столу стоит **на сдаче**, а не на выдаче: выдачу отдаёт
`content-bundle` без токена и без сессии, фильтр там был бы украшением. Чужая
сдача ломает по-настоящему — сбивает такт соседа и очередь его партнёра.

## Маршруты

| Маршрут | Кто ходит |
|---|---|
| `/tools/mayak-oko` | участник, как и в первый день |
| `POST /api/mayak/session-runtime/card-number` | участник называет свой тайл |
| `GET /api/mayak/session-runtime/team` | командный экран, без входа |
| `POST /api/mayak/master/day2-takt` | ведущий по ссылке или методолог из админки |
| `/mayak-day2-team?session=<id>&table=1` | ноутбук команды, открыт весь день |

## Debug-сессия снимает правила намеренно

Вход `fffffday2` поднимает сессию с `source: "debug"`. В ней сняты: требование
роли инспектора, привязка к столу и партнёрская маршрутизация. Иначе один
человек не прошёл бы день соло, а прогон нужен чаще, чем зал.

Настоящие правила проверяются скриптами, не браузером:

```
node scripts/check-day2-pairing.mjs
node scripts/check-day2-takt.mjs
```

Оба поднимают свою сессию через админский API и удаляют её за собой. Нужен
запущенный дев-сервер.

## Контент

`scripts/make-day2-section.py` пишет секцию `day2`: 18 деталей, 9 узлов,
9 переходников, 3 сборки. Тексты — рыба из примеров ТЗ; настоящие соберёт
модуль А из расшифровки встречи организации.

Проверка внутри скрипта следит, чтобы колода билась с тем, что открывает разбор
ввода: расхождение ловится генератором, а не участником в 14:00.

## Чего нет

- **модуля А** — сборки карточек из расшифровки встречи;
- **блока 10:55** — вчерашней карточки, переноса `participantId` между днями;
- **ссылки на папку команды** на командном экране: её негде хранить;
- **учебных деталей 41–46** для проверки на чужом материале в 17:15.

## Открытый вопрос, который решает человек

**Нумерация пар: `13-14` против `15-16`.** Фото тайлов и промпт-фреймворк
расходятся. Тираж печатается по фото. Пока вопрос не закрыт, участник рискует
получить не своё задание — и код тут ни при чём.
