# Второй день во фронтенде · архитектура и порядок работ

Документ отвечает на один вопрос: что и где меняется, чтобы платформа проводила
второй день. Написан после чтения кода, а не только ТЗ — все ссылки на файлы
проверены.

## Принцип: три слоя, и второй день не добавляет четвёртого

| Слой | Что отвечает | Где живёт | Что меняется |
|---|---|---|---|
| **Контент** | что показать | `data/mayak-content/<sectionId>/` | новая секция `201-300` |
| **Рантайм** | что сделано | `session-runtime`, `participant.tasks` | ничего в схеме |
| **Экран** | как показать | `src/components/features/tools-2/` | новый ввод и новый автомат |

Второй день — **третья секция контента и второй автомат фаз**, а не вторая
система. Это и определяет объём: он меньше, чем кажется по ТЗ.

## Что переиспользуется как есть

Проверено в коде, трогать не нужно:

- **Столы, роли, инспектор** — `src/lib/mayakSessionRuntime.js`. Инспектор
  назначается кольцом: стол `N` проверяет стол `N+1`, последний первый
  (`getInspectorTargetTable`, строка 158). Та же геометрия, что у тайлов.
- **Сдача, проверка, файлы, блокировки** — `/api/mayak/session-runtime/{state,
  participant,role,review,upload,file}`.
- **Колода по секции** — `useMayakTaskManager`. Номер задания уже живёт в
  `taskNumber`, `rangeStart` переводит номер в позицию колоды.
- **Конструктор МАЯК ОКО**, семь полей — `data/mayakData.json`, `fieldsList`.
- **Состояние задания по номеру** — `participant.tasks`, ключ
  `buildTaskKey(taskNumber)`, статусы `pending → pending_review → approved |
  rejected | expired`.

**Ключевое наблюдение.** `participant.tasks` — словарь по строковому ключу
внутри сессии. Значит узел `13-14` и сборка `среда` ложатся туда же, без
изменения схемы: меняется только то, что кладётся в ключ.

## Чего нет и что добавляется

### 1. Ввод номера · новый экран

В первом дне участник номер **не вводит**: он идёт по колоде индексом
(`currentTaskIndex` в `useMayakTaskManager`), а токен ограничивает диапазон.
Во втором дне номер приходит с картона.

Одно поле, четыре вида ввода:

```
13                    → карточка детали
13 14 · 1314 · 13-14  → карточка узла
13 14 не сошлось      → переходник
среда                 → карточка сборки
```

**Не делать три поля.** Участник в 12:40 не должен выбирать вкладку — он должен
набрать то, что видит на столе.

Новый модуль: `src/lib/mayakDay2Input.js` — чистая функция

```
parseDay2Input(raw) → { kind, key, numbers } | null
   kind: "detail" | "node" | "adapter" | "assembly"
   key:  "13" | "13-14" | "13-14:adapter" | "sreda"
```

Пара **нормализуется по возрастанию**: `14 13` и `13 14` дают один ключ.
Иначе аналитика посчитает два узла вместо одного.

### 2. Автомат тактов · новый вывод, не новое хранилище

Образец уже есть: `src/lib/mayakProgressModel.js`, `computeProgress` —
фаза **вычисляется** из сданных заданий и нигде не хранится.

Второй день делается так же: `src/lib/mayakDay2Takt.js`

```
computeTakt({ taskStates, tableComposition }) → { takt, done, total }
   takt: "DETAIL" | "NODE" | "PRODUCT"
```

- `DETAIL` — пока не сданы шесть деталей стола;
- `NODE` — пока не сданы три узла;
- `PRODUCT` — дальше.

**Такт не хранить флагом.** Иначе табло ведущего и экран участника разойдутся,
и разбираться будут в зале.

### 3. Три типа карточек · три поля в схеме

Карточка сейчас — 22 поля, из них **три мёртвых**: `hasSource`, `sourceLink`,
`services`, ноль непустых из ста. ТЗ предлагает занять их:

| Новое поле | Куда | Пример |
|---|---|---|
| `question` | `TaskText.json`, рядом с `description` и `task` | *как сделать, чтобы внёс сам?* |
| `partnerNumber` | `index.json` | `"14"` |
| `dueMidday` | `TaskText.json` | *справочник виден по ссылке* |

Переименование дешевле миграции — решение за разработчиком, но занимать стоит:
добавление поля в 22-полевую схему тянет за собой админку и валидацию.

### 4. Оценка промпта выключается

Во втором дне `sova-check` не работает (ТЗ, раздел В5). Нужен флаг уровня
секции или сессии, а не правка хука: `useMayakSovaEvaluation` остаётся как есть,
но не вызывается.

## Модель данных · что где лежит

```
data/mayak-content/201-300/
  index.json        карточки: 22 поля + partnerNumber
  meta.json         rangeStart 201, rangeName
  TaskText.json     description, task, question, dueMidday

data/mayak-session-runtime.json
  participant.tasks {
    "13":            деталь       такт 1
    "13-14":         узел         такт 2
    "13-14:adapter": переходник   такт 2, не всплывает сам
    "sreda":         изделие      такт 3
  }
```

Одна запись — одно состояние. Статусы те же, что в первом дне.

**Номер — координата, не идентификатор.** Тайл `13` печатается один раз и служит
годами, значит один номер будет у сотни сессий. Ключ всегда `sessionId +
cardNumber`; запрос по номеру без сессии вернёт мусор из всех сразу. Это самая
вероятная ошибка реализации: номер выглядит как ключ и напрашивается им стать.

## Порядок работ

Каждый шаг проверяем до перехода к следующему.

| # | Шаг | Проверка |
|---|---|---|
| 1 | `mayakDay2Input.js` — парсер ввода | `node --test`: четыре вида ввода, нормализация пары, мусор даёт `null` |
| 2 | `mayakDay2Takt.js` — автомат тактов | `node --test`: шесть деталей → `NODE`, три узла → `PRODUCT` |
| 3 | Секция `201-300` фикстурой, руками | `/api/mayak/content-bundle?sectionId=201-300` отдаёт 21 карточку |
| 4 | Экран ввода + карточка детали | вживую: ввёл `13`, открылась карточка, сдал, партнёр оценил |
| 5 | Узел и переходник | `13 14` и `13 14 не сошлось` пишутся разными ключами, порядок номеров не важен |
| 6 | Сборка и чек-лист | `среда` открывает шесть пунктов, дословно совпадающих с подложкой |
| 7 | Табло дня | читает те же `taskStates`, ничего своего не хранит |

Шаги 1 и 2 — чистые функции без React и без сети: делаются за раз, ломать
ничего не могут, и от них зависит всё остальное.

Шаг 3 намеренно **до** модуля А. Секцию можно положить руками одной сессией,
и тогда экраны разрабатываются на настоящих данных, не дожидаясь генератора.

## Что не трогаем

**Первый день.** Секция `1-100`, её автомат фаз и часть «Я» остаются как есть.
Общее у двух дней — конструктор полей и механика сдачи; всё остальное
параллельно и не пересекается.

Легаси-пути (`src/components/features/tools/`, `mayak-oko-stable`) не трогаем
тем более.

## Решения, которые принимает человек

1. **Номера пар `13-14` и `15-16`** спорят между фотографией набора и каркасом
   промптов. На картоне застынет навсегда, в промпте правится без деплоя. Пока
   не решено — фикстуру секции делать нельзя, номера будут неверные.
2. **Занимать мёртвые поля или добавлять новые** в схему карточки.
3. **Порядок столов** — `2x` Деятельность и `3x` Сознание против модели ССД,
   где Сознание идёт вторым.

Первое блокирует шаг 3, остальные два — нет.
