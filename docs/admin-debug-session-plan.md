# План: режим «Админ-отладка внутри сессии» (session-токен + fffff)

## Цель
Администратор заходит по сессионному токену с суффиксом `fffff` в **ту же** сессию:
- видит и использует весь функционал сессии (роли, выбор направления, отправка задания,
  проверка инспектора, джокер, прогресс Я/ИЦЗ);
- имеет панель отладки (быстрые шорткаты);
- **ничего не записывается** на сервер — ни вход, ни прогресс, ни проверки.

## Корневая причина текущего поведения
`src/pages/api/mayak/validate-token.js`: `detectAdminBypass()` срабатывает на суффикс `fffff`
ДО валидации сессии → возвращает `tokenType: "bypass"` (вне сессии, без роли).

## Подход: эфемерная сессия на клиенте (read с сервера, write — локально)
GET-чтение состояния разрешено (не мутирует). Все write-вызовы при `adminDebug`
не уходят на сервер, а применяются к локальной копии состояния (в памяти/localStorage).

### Изменения

1. **validate-token.js**
   - Ввести снятие суффикса `fffff` так же, как снимается гостевой `aaaaa`,
     и СНАЧАЛА проверять сессионный токен.
   - Если «очищенный» токен — валидная активная сессия И присутствовал суффикс
     отладки (`fffff` на localhost / `MAYAK_ADMIN_BYPASS_SECRET` на проде):
     вернуть `tokenType: "session"`, обычные поля сессии + `adminDebug: true`,
     `adminBypass: true` (права админа), но **без** `isBypass: true`.
   - Если очищенный токен не является сессией → текущее поведение (pure bypass)
     сохраняется без изменений (обратная совместимость).

2. **Вход (settings.js)**
   - При `adminDebug` писать cookie: `tokenType: "session"`, `sessionId`, `sessionName`,
     `adminDebug: true`, БЕЗ записи участника на сервер (не вызывать register).
   - Стол/роль администратор выбирает локально (см. п.4).

3. **useMayakRuntimeData**
   - Пробросить `adminDebug` из cookie.

4. **trainer.js — эфемерное состояние**
   - Локальный `debugRuntimeState` (участник: role, tableNumber, yaDirection,
     jokerSpent, tasks{}), сидится из реальной сессии (sectionId/tableCount берём
     из ответа state GET, чтобы колода/прогресс совпадали с настоящей сессией).
   - `isSessionMode` оставить true; но при `adminDebug`:
     - НЕ поллить участника с сервера для записи (или накладывать локальный оверлей);
     - `sessionRuntimeState` = `debugRuntimeState`.
   - Перехват write-обработчиков (при `adminDebug` — без fetch, мутируем локально):
     - регистрация участника;
     - `handleRoleConfirm` (роль/целевой стол инспектора);
     - `handleYaDirectionConfirm`;
     - `handleSessionTaskUpload` → ставит задачу в `pending_review` локально;
     - `handleResolveInspectorReview` → локально approve/reject;
     - `handleUseJokerStar` → локально approve + jokerSpent.
   - «Быстрая проверка инспектора» в панели отладки: кнопка, мгновенно
     переводящая текущее отправленное задание в `approved` локально
     (без второго участника — единственное неизбежное упрощение).

5. **Панель отладки (уже улучшена)**
   - Добавить переключатель роли (Участник/Инспектор/Администратор) и
     кнопку «Одобрить текущее задание (отладка)».
   - Существующие шорткаты этапов Я/ИЦЗ и индикатор джокеров остаются.

## Принцип неизбежного упрощения
Реальный цикл «двух людей» (участник↔инспектор) одним админом без записи на сервер
не воспроизводится 1:1. Поэтому «проверка инспектора» в отладке = локальное
мгновенное одобрение (или локальный self-review через тот же модал инспектора).

## Что НЕ трогаем
- Реальный сессионный поток (без `fffff`) — без изменений.
- Серверные API/файлы `data/*` — не пишутся в режиме отладки.
- Существующий pure-bypass (`fffff` без валидной сессии) — сохраняется.

## Проверка
- Вход по сессионному токену БЕЗ `fffff` → как раньше (роль из сессии, записи идут).
- Вход с `fffff` → та же сессия, панель отладки, ни одной записи в `data/mayak-session-runtime.json`
  (проверить mtime/содержимое файла до/после).
- Компиляция webpack без ошибок.
